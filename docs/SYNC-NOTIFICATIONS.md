# 自动恢复与即时同步

WebDAV 继续保存历史、增量记录、附件和设置。MQTT 只通知其他设备“有更新”，接收端随后从 WebDAV 拉取。

## 使用条件

- 两端使用支持此功能的 TieZ 桌面客户端。
- 开启 WebDAV 自动同步，并使用相同地址、账号和同步目录。
- 开启 MQTT，使用相同服务器和主题。
- MQTT 服务允许客户端发布、订阅下述通知主题。若权限不足或 MQTT 不可用，原有 WebDAV 定时同步继续工作。

原有短信、文本消息接收不变。手动同步模式不会因通知或网络恢复而自动启动同步。

## 通知协议

通知主题为 `tiez-sync/v1/<SHA-256(MQTT主题)>/changed`，位于原有剪贴板主题之外，避免旧客户端把通知当作正文。
MQTT 主题计算前去除首尾空白与末尾 `/`。消息使用 QoS 1，`retain=false`。

```json
{
  "v": 1,
  "kind": "webdav_changed",
  "scope": "<WebDAV位置的SHA-256摘要>",
  "device_id": "<发送端设备标识>",
  "event_id": "<随机UUID>"
}
```

`scope` 由规范化后的 WebDAV URL、账号、同步目录生成；通知不包含正文、网址、账号或密码。
只有全部资源及同步索引成功上传并验证后才发通知。通知失败不影响 WebDAV 的上传结果。

接收端忽略自身回声、其他同步位置、重复事件、保留消息、无效版本及格式错误。
所有 `tiez-sync/` 消息都与剪贴板正文分开处理。重复事件缓存有大小上限。
通知通过已有串行同步任务处理，繁忙时保留一次待处理请求；空闲时立即唤醒，不等轮询间隔。

## 网络恢复

- 每 5 秒检查本地接口地址和默认出口地址，变化时重新建立 MQTT 连接并请求 WebDAV 同步。
- macOS 和 Windows 的唤醒通知触发恢复；超过 20 秒的检查间隔辅助识别睡眠恢复。
- 连续恢复事件在 10 秒内合并，期间的新变化保留到下一次检查。
- MQTT 重连成功后请求一次同步，补拉离线期间的更新。
- 重启请求能中断 MQTT 的连接等待、空闲等待及重连退避。
- 默认 MQTT 连接名基于本机设备标识生成。同一主题的设备拥有不同连接名；手动填写的连接名保持原值。

接口检查不能识别所有地址不变的网络切换；MQTT 心跳重连和 WebDAV 轮询继续兜底。

## 验证

自动测试覆盖通知主题隔离、实际 MQTT 报文、重复与自身回声、同步位置隔离、保留消息、异常消息、
断网恢复、唤醒、恢复事件合并、退避上限、同步请求唤醒及定时同步兜底。

两台设备验收时，可将轮询间隔设为 120 秒：在一端新增或删除记录，确认另一端不等完整间隔即可更新；
暂停另一端网络后继续复制，恢复连接，确认历史补齐且没有通知 JSON 出现在剪贴板中。
